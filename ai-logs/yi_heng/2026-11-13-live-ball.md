# AI Log — Live ball every 3 seconds and ball colours

- **Date:** 2026-11-13
- **Team member:** Yi Heng
- **AI tool / model:** Claude Code, Opus
- **Objective:** Update the live location at least every 3 seconds so the ball stays close to the real position,
  and let students change the ball's colours.

## AI Prompts Used
1. "make it so that the location tracking is every 3 second interval minimum ... add color changes to the ball too
   to have more customizations."

## Decisions Made
- Read "every 3 second interval minimum" as "at least every 3 seconds": when the browser's watch has been quiet for
  2 s, the map restarts it (a new watch starts with a fresh fix, so it arrives within 3 s). A restart still waiting
  gets 6 s before the next one; nothing while the tab is hidden; a refusal switches the live position off as before.
  Readings still stay in the browser; the location check of an attempt is unchanged.
- First version used one-off readings (`getCurrentPosition`). The browser tests showed that with a simulated position
  (also DevTools, used in the location testing guide) such a reading never answers while a watch runs and then
  blocks the location check, so it was replaced by restarting the watch, and a browser test now checks both.
- Ball colours are part of the existing map style (BR48): `ball.body` and `ball.lines` (the lines also tint the
  direction wedge), checked on the server like the other colours; two new colour chips, a ball in the preview, and
  each preset has a matching ball. The default ball stays white with red lines. BR48's text in
  `docs/business-rules.md` was extended: needs the team's approval.
- New tests (unit, component, API, browser: `frontend/e2e/live-refresh.spec.js`) and two regression tests. Nothing was committed by the AI.

## Session 2 — fluid and sensitive ball
- **Prompt:** "make the animations of the ball and rolling animations and the user icon more fluid and also more
  responsive ... even if there is a little change, the ball would also sense it ... updated every few seconds".
- The ball now follows the position every frame (eases towards the newest reading, walks on at the measured pace
  for at most 2 s between readings, sleeps when still) instead of gliding 350 ms and then standing still; it rolls
  along every frame. The filter follows faster (drift 30 instead of 9 m²/s), direction from 4 m and 0.5 m/s,
  compass arrow from 2°, wedge turns the short way round. Readings still at least every 3 s. Tests and a regression
  test added; nothing committed by the AI.
